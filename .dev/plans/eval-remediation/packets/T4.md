## §1 Task statement

Implement the five-priority eval remediation strategy for the minivii NLP pipeline. Case 1 ("most bought product on Fridays") is misclassified as `TIME_FILTER` instead of `AGGREGATION` because `KEYWORD_CLASS_MAP` checks `TIME_FILTER` before `AGGREGATION` and `"on friday"` matches before `"most"`. This subtask (Wave 2) adds an `AGGREGATION_OVERRIDES` constant and a post-scan override rule, and creates a new dedicated test file for classifier coverage.

**Non-goals (this subtask):**
- Multi-label / scored classification — out of scope; Option C (priority overrides) only.
- LLM fallback changes — `_llm_classify` path unchanged.
- Returns guard or disambiguation — owned by T3/T2.
- Narrative hardening — owned by T5.
- `TEST_CASES` edits in harness — T4 confirms `expected_class=aggregation` for case 1 is already correct and no edit is needed; if it is not correct, HALT.

## §4 Subtask spec

**ID:** T4  
**Scope:** Add `AGGREGATION_OVERRIDES` constant to `query_classifier.py`. After the `KEYWORD_CLASS_MAP` keyword scan, if any override term is present in the question AND any TIME_FILTER keyword also matched, force the class to `AGGREGATION` with method string `"heuristic_override"`. Create `nlp/tests/test_query_classifier.py` with tests covering: case 1 pattern → `AGGREGATION`; case 2 pattern → `TIME_FILTER` (no regression); `"most bought on Fridays"` → `AGGREGATION`.

**Files to touch:**
- `nlp/pipeline/query_classifier.py` — `AGGREGATION_OVERRIDES` constant, `classify` function
- `nlp/tests/test_query_classifier.py` — new file

**Contract bindings:** All §2 contracts above apply. Override must only fire when a TIME_FILTER keyword AND an override term co-occur — bare aggregation terms with no time keyword must not change the class for pure aggregation inputs. T4 must not modify `TEST_CASES` in `harness.py`.

**Inputs:** T2 complete (classification runs on `resolved.resolved` string — P1 disambiguation suffix must be stable before override predicates are tested against case patterns).

**Outputs:**
- Modified `query_classifier.py` with `AGGREGATION_OVERRIDES` and override logic in `classify`
- New `nlp/tests/test_query_classifier.py` with ≥3 test cases

**Kill criteria:**
1. If `KEYWORD_CLASS_MAP` iteration order is not deterministic Python dict in the current code (i.e., not guaranteed to check TIME_FILTER before AGGREGATION) — **HALT**: report the actual iteration mechanism and key order found.
2. If `classify` returns a 3-tuple or any other shape than `(QueryClass, str)` — **HALT**: report the actual return shape.
3. Case 2 regression test (`"how many transactions on Saturday"` or the equivalent pattern from `TEST_CASES[1]`) must yield `TIME_FILTER`, not `AGGREGATION`. If the override predicate cannot be written narrowly enough to guarantee this — **HALT**: report the conflict and proposed resolution.
4. `pytest nlp/tests/test_query_classifier.py -x` must pass (no live LLM calls in the new test file).

**Log tier:** standard

**Risks & mitigations:**
- `"what day has the most transactions"` — legitimately TIME_FILTER but contains `"most"`; override must require explicit ranking terms (`"most bought"`, `"top"`, `"best"`) not bare `"most"` when combined with a day-filter; document this in the test matrix comments.
- `classify` calls `_llm_classify` as fallback; override must inject before the return path, not before the LLM fallback.
- T4 is parallel with T3 — they touch disjoint files; coordinate on `harness.py:TEST_CASES`: T3 must not touch it, T4 confirms case 1 `expected_class`.
