## §1 Task statement

Implement the five-priority eval remediation strategy for the minivii NLP pipeline. Four cases show judge issues despite correct SQL — failures cluster on comparative, temporal, and derived claims. This subtask (Wave 3) hardens the synthesis prompt with explicit constraints against unsupported claims, and enriches the judge prompt with per-case business rules where available.

**Non-goals (this subtask):**
- `result_assertions` on `TestCase` — deferred (Flag 5 resolution).
- `known_answer` fuzzy matching — deferred.
- SQL post-processor — out of scope.
- Pipeline stage changes (disambiguation, returns, classifier) — owned by T2/T3/T4.
- Temperature reduction below `0.3` — only change if strategy §5 explicitly recommends a lower value; check before changing.
- Architecture doc updates.

## §4 Subtask spec

**ID:** T5  
**Scope:** Harden `result_synthesizer._build_synthesis_prompt` with explicit constraints against unsupported comparisons, derived arithmetic claims, and temporal labels not present in data. Enrich `judge_synthesis` prompt with per-case business rules when `TestCase.known_answer` is not None or when the question involves returns/weekly deltas (use `known_answer` as proxy signal). Extend `test_result_synthesizer.py` to assert the constraint block is present in the built prompt. Check strategy §5 for temperature recommendation; only change `temperature` if §5 explicitly recommends a value below `0.3`.

**Files to touch:**
- `nlp/pipeline/result_synthesizer.py` — `_build_synthesis_prompt`
- `nlp/eval/harness.py` — `judge_synthesis` prompt enrichment
- `nlp/tests/test_result_synthesizer.py` — prompt shape assertion
- `nlp/tests/test_harness.py` — judge prompt enrichment test (prompt string only; no LLM call)

**Contract bindings:** All §2 contracts above apply. `result_assertions` / `TestCase` extension is **out of scope** (Flag 5, deferred). Judge enrichment must pass business rule text only when a rule is available — no structural change to `TestCase` dataclass.

**Inputs:** T3 and T4 complete (SQL and classification fixes in place; narrative issues are genuinely in the narrative layer, not upstream).

**Outputs:**
- Modified `result_synthesizer.py` with hardened prompt constraints
- Modified `harness.py` with enriched judge prompt path
- Extended tests for prompt shape

**Kill criteria:**
1. If `_build_synthesis_prompt` current signature does not match `(question, data, sql, interpretations_applied, steps_taken)` as recorded in the context map — **HALT**: report the actual current signature before making any changes.
2. If `judge_synthesis` signature does not match `(question, result_data, narrative)` — **HALT**: report the actual signature.
3. Prompt constraint block must contain at least one explicit prohibition substring (e.g. `"Do not"` or `"Only report"`) verifiable by a substring assertion in `test_result_synthesizer.py`.
4. `pytest nlp/tests/test_result_synthesizer.py -x` must pass.
5. If `TestCase` does not have a `known_answer` field at all (structure changed) — **HALT**: report the actual `TestCase` fields before writing judge enrichment logic.

**Log tier:** standard

**Risks & mitigations:**
- Over-constraining synthesis may reduce fluency on clean cases — constraints must target comparative/derived claims only; scalar reporting cases (4, 5, 7, 8, 9, 10) must not degrade; note this intent in a comment near the constraint block.
- Judge prompt enrichment uses `known_answer` as proxy for case 12 — case 12 has `known_answer = None` in current harness, so enrichment will not fire for it; this is a known limitation (Flag 7 / deferred `result_assertions`); note in changelog.
- Synthesis model and judge model are likely the same (Surface 10, suspected) — T5 hardening may not reduce judge scores even if synthesis improves; this is an accepted residual for this plan version.
