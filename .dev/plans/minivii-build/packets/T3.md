## §1. Task Statement

Build Mini Nivii — a domain-scoped NL-to-SQL BI agent. This subtask implements all upstream pipeline components: `LLMClient`, `SemanticLayer`, `AmbiguityDetector`, `SchemaLinker`, `QueryClassifier`, `SQLGenerator` (including `extract_sql` and `FEW_SHOT_EXAMPLES`). These components include **live LLM calls** via `LLMClient` — `QueryClassifier._llm_classify` and `SQLGenerator.generate_sql` both call the LLM and must be fully wired, not stubbed. "Upstream" means: no HTTP calls to the `db` service, and no ReAct loop execution. LLM inference via `LLMClient` is fully in scope. The downstream ReAct loop and Pipeline orchestration are built in T4.

**Non-goals:**
- `SQLExecutor`, `ResultSynthesizer`, `Pipeline` — those are T4
- FastAPI wrapper for the nlp service — that is T4
- LLM-based AmbiguityDetector (rule-based is the spec; LLM path is a production enhancement)
- Retrieval-augmented SchemaLinker (full injection at this scope; ChromaDB is a production enhancement)
- HTTP calls to the `db` service (that is SQLExecutor's territory in T4)
- Unit tests that require a running LLM (tests mock or skip LLM calls; the live wiring is validated by T6's eval harness)

**Kill criteria:**
- HALT if `AmbiguityDetector.detect_and_resolve` applies rules incrementally (the resolved output of rule N is passed as input to rule N+1) — must collect all matches against the ORIGINAL question then compose once
- HALT if `QueryClass` enum values deviate from `{TIME_FILTER="time_filter", WINDOW="window", AGGREGATION="aggregation", SIMPLE="simple"}`
- HALT if `FEW_SHOT_EXAMPLES` keys do not match all four `QueryClass` members (must include all four)
- HALT if `extract_sql` raises an exception on any input — it must return the raw string when no SELECT/WITH is found
- HALT if `LLMClient` does not support `backend` in `{"ollama", "groq", "together"}`
- HALT if prompt order in `build_sql_prompt` deviates from spec §5.5: schema → KPIs → few-shot → question → output instruction
- HALT if `SchemaLinker` adds any retrieval logic or external dependency (ChromaDB, embeddings, etc.)
- HALT if unit tests require a running LLM to pass (mock or skip LLM calls in tests; live wiring is validated by T6)
- **HALT if `FEW_SHOT_EXAMPLES[QueryClass.WINDOW]` uses `substr(` for date manipulation instead of `strftime('%Y-W%W', date)`** — the window example must use `strftime` directly on the ISO-normalized date column. The broken `substr()` formula is the v7 bug (spec correction C1); transcribing it into the few-shot example silently injects it into every window query generation.

**Risks & mitigations:**
- `SchemaLinker` is a thin wrapper. Implement as `link(question) -> str` returning `self.semantic_layer.render_ddl()`. The `question` parameter is accepted for forward-compatibility with the retrieval path but ignored at this scope.
- `LLMClient._litellm_generate` requires `litellm` installed. If litellm is not in requirements.txt, add it. The `ollama` package is for the `_ollama_generate` path.
- The `_llm_classify` fallback in QueryClassifier should use `temperature=0.0` for deterministic output.

## Key Implementation Reference

### `ambiguity_detector.py` — verbatim from spec §5.3

```python
from dataclasses import dataclass, field

@dataclass
class ResolvedQuestion:
    original: str
    resolved: str
    interpretations_applied: list[str] = field(default_factory=list)

AMBIGUITY_TRIGGERS: dict[str, str] = {
    "most":        "most bought / most popular product",
    "popular":     "most bought / most popular product",
    "top":         "top N without explicit metric",
    "best":        "top N without explicit metric",
    "recent":      "recent without explicit time window",
    "latest":      "recent without explicit time window",
    "busiest":     "busiest / most active",
    "active":      "busiest / most active",
    "last month":  "last month / this month",
    "this month":  "last month / this month",
}

def detect_and_resolve(question: str, domain_descriptor: dict) -> ResolvedQuestion:
    fired_axes: dict[str, dict] = {}

    # Collect all matches against the ORIGINAL question — do not cascade
    for trigger, axis in AMBIGUITY_TRIGGERS.items():
        if trigger in question.lower() and axis not in fired_axes:
            rule = lookup_disambiguation_rule(axis, domain_descriptor)
            if rule:
                fired_axes[axis] = rule

    if not fired_axes:
        return ResolvedQuestion(original=question, resolved=question)

    qualifiers = []
    interpretations = []
    for axis, rule in fired_axes.items():
        qualifier = rule.get("apply", "")
        if qualifier:
            qualifiers.append(qualifier)
        interpretations.append(f"{axis}: {qualifier}")

    # Single composition: original question + joined qualifiers (appended once)
    base = question.rstrip("?.!")
    resolved = base + " — " + "; ".join(qualifiers) if qualifiers else question

    return ResolvedQuestion(
        original=question,
        resolved=resolved,
        interpretations_applied=interpretations,
    )
```

### `query_classifier.py` — verbatim from spec §5.4

```python
from enum import Enum

class QueryClass(Enum):
    TIME_FILTER  = "time_filter"
    WINDOW       = "window"
    AGGREGATION  = "aggregation"
    SIMPLE       = "simple"

# Priority order: more specific classes first. Do not reorder.
KEYWORD_CLASS_MAP: dict[QueryClass, list[str]] = {
    QueryClass.TIME_FILTER: [
        "on monday", "on tuesday", "on wednesday", "on thursday", "on friday",
        "on saturday", "on sunday", "on weekends", "on weekdays",
        "in the morning", "in the afternoon", "peak hour", "busiest hour",
        "what hour", "what time", "what day",
    ],
    QueryClass.WINDOW: [
        "trend", "week-over-week", "month-over-month", "over time",
        "growth", "change over", "evolution", "compared to last",
    ],
    QueryClass.AGGREGATION: [
        "most", "top", "best", "total", "average", "how many",
        "sum", "by product", "by waiter", "per product", "per waiter",
        "breakdown", "ranking",
    ],
}

def classify(question: str, llm_client) -> tuple[QueryClass, str]:
    q = question.lower()
    for cls, keywords in KEYWORD_CLASS_MAP.items():
        if any(kw in q for kw in keywords):
            return cls, "heuristic"
    return _llm_classify(question, llm_client), "llm"
```

### `sql_generator.py` — `extract_sql` and `FEW_SHOT_EXAMPLES`

```python
import re

def extract_sql(response: str) -> str:
    response = re.sub(r"```sql|```", "", response).strip()
    match = re.search(r"\b(SELECT|WITH)\b", response, re.IGNORECASE)
    if match:
        sql = response[match.start():]
        if ";" in sql:
            sql = sql[:sql.index(";") + 1]
        return sql.strip()
    return response  # caller handles — do not raise
```

`FEW_SHOT_EXAMPLES` must include all four keys matching `QueryClass` enum members. Use the verbatim examples from spec §5.5.

### Prompt order in `build_sql_prompt` (spec §5.5 — binding)

1. CREATE TABLE schema (from `linked_schema`)
2. KPI definitions
3. Structural few-shot example (`FEW_SHOT_EXAMPLES[query_class]`)
4. Resolved question
5. Output instruction: "Return only the SQL query. No explanation. No markdown fences."

Temperature must be 0.0 for `generate_sql` calls.
