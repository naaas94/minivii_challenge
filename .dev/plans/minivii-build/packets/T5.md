## §1. Task Statement

Build Mini Nivii — a domain-scoped NL-to-SQL BI agent. This subtask implements the `ui` FastAPI + Jinja2 service: a single HTML page that accepts a natural language question, calls the `nlp` service, and renders the narrative (bold), SQL (collapsible), result table, and interpretation notes. Loading state is mandatory given the 3–7 minute inference latency.

**Non-goals:**
- `nlp` service — that is T4 (already built)
- `db` service — that is T2 (already built)
- Evaluation harness — that is T6
- README — that is T7
- WebSocket or streaming responses (synchronous fetch with spinner is the correct approach)

## §2. Shared Contracts

### Types / Interfaces (consumed from T4)

`PipelineResult` fields rendered in the template:
```
result.question              str
result.resolved_question     str
result.interpretations       list[str]    (non-empty = disambiguation fired)
result.query_class           str          (e.g. "aggregation")
result.sql                   str
result.execution.success     bool
result.execution.data        list[dict] | None
result.execution.columns     list[str] | None
result.execution.steps_taken int
result.narrative             str | None
```

**Note:** The `nlp POST /query` response is JSON (serialized in T4 via `dataclasses.asdict`). In T5, `response.json()` returns a plain Python dict. Pass this dict directly to `TemplateResponse`. In the Jinja2 template, `result.narrative` and `result.execution.success` work via Jinja2's attribute/key fallback — both dot notation and bracket notation work on dicts in Jinja2 templates. **T5 does not call `dataclasses.asdict()` — it never holds the dataclass object.**

### Error Envelope

| nlp Endpoint | Success shape | Error shape |
|---|---|---|
| `POST /query` | Serialized `PipelineResult` as JSON dict | `{"error": "message"}` with HTTP 200 |

The UI must handle both cases gracefully. If `response["error"]` key exists, show a friendly error message — never a raw Python traceback.

### Naming
- Port: **3000**
- nlp service URL: `http://nlp:8002` (hardcoded or from env var `NLP_URL`)
- Templates directory: `ui/templates/`

### Tests
No unit tests required for T5. Visual smoke test: submit the canonical question "What is the most bought product on Fridays?" and verify the result renders correctly with narrative, SQL, and result table.

**Contract bindings:** §2 Error Envelope (nlp response shapes), §2 Naming (port 3000, NLP URL), §2 Types (`PipelineResult` field names as dict keys).

**Inputs:** T4 — `PipelineResult` fields listed above (via HTTP).

**Outputs:**
1. `ui/main.py`: FastAPI app on port 3000; `GET /` returns blank form; `POST /` submits question to nlp, renders result
2. `ui/templates/index.html`: full HTML page with all required UI elements

**Required UI elements:**
- Natural language input field and submit button
- **Loading/spinner state** visible immediately on submit, stays until response arrives (use JS fetch + async)
- **Narrative** rendered in bold (`<strong>`) or equivalent visual prominence
- **SQL** in a collapsible `<details>/<summary>` block
- **Result table** rendered from `execution.data` (columns as headers, rows as data)
- **Interpretation notes** block — only shown when `interpretations` list is non-empty; lists each applied rule
- **Error state** — friendly message when `execution.success` is false or `error` key present; no raw tracebacks
- **Steps taken** — show `execution.steps_taken` somewhere (transparency requirement from spec)
- **Query class** — show `query_class` (transparency requirement)

**Kill criteria:**
- HALT if UI shows a raw Python traceback or HTTP 500 page on any handled error
- HALT if SQL section is not collapsible (must use `<details>/<summary>` or equivalent toggle)
- HALT if loading/spinner state is absent — given 3–7 min latency, this is a critical UX failure
- HALT if narrative is not visually differentiated from surrounding text (must be bold or equivalent)
- HALT if `ui/main.py` uses a synchronous HTTP call that blocks the ASGI worker — use `httpx.AsyncClient` with `await`
- HALT if the result table crashes when `execution.data` is None or empty (must handle gracefully)
- **HALT if `httpx.AsyncClient` is constructed without an explicit timeout of at least 600 seconds** — `httpx.AsyncClient(timeout=httpx.Timeout(600.0))`. The default read timeout is 5 seconds; model inference takes 3–7 minutes. Without this, `httpx.ReadTimeout` fires after 5s, the handler returns an error response regardless of the spinner state, and the query is silently aborted.

**Risks & mitigations:**
- The `POST /` handler must use `async def` and `await` with `httpx.AsyncClient(timeout=httpx.Timeout(600.0))` to avoid both blocking the ASGI event loop and the 5-second default read timeout. The timeout object form (`httpx.Timeout(600.0)`) sets connect, read, write, and pool timeouts uniformly to 600s.
- Jinja2 autoescape is enabled by default in FastAPI's `Jinja2Templates`. SQL strings with angle brackets or special characters will be escaped. Use `{{ sql | safe }}` in the template only if you're confident the SQL is safe (it is — it's generated SQL, not user input).
- The spinner should use CSS animation or a simple animated GIF. No external CDN calls — the submission system is air-gapped.

## Key Implementation Reference

### `ui/main.py` — structure

```python
from fastapi import FastAPI, Request, Form
from fastapi.responses import HTMLResponse
from fastapi.templating import Jinja2Templates
import httpx
import os

app = FastAPI()
templates = Jinja2Templates(directory="templates")
NLP_URL = os.environ.get("NLP_URL", "http://nlp:8002")

@app.get("/", response_class=HTMLResponse)
async def index(request: Request):
    return templates.TemplateResponse("index.html", {"request": request, "result": None})

@app.post("/", response_class=HTMLResponse)
async def query(request: Request, question: str = Form(...)):
    result = None
    error = None
    try:
        async with httpx.AsyncClient(timeout=httpx.Timeout(600.0)) as client:  # 10 min; default is 5s which is too short
            response = await client.post(f"{NLP_URL}/query", json={"question": question})
            data = response.json()
            if "error" in data:
                error = data["error"]
            else:
                result = data
    except Exception as e:
        error = f"Service unavailable: {str(e)}"
    return templates.TemplateResponse("index.html", {
        "request": request,
        "question": question,
        "result": result,
        "error": error,
    })
```

### `ui/templates/index.html` — required structure

```html
<!DOCTYPE html>
<html>
<head>
  <title>Mini Nivii — BI Agent</title>
  <style>
    /* spinner, layout, narrative bold, table styles */
  </style>
</head>
<body>
  <h1>Mini Nivii</h1>
  <form id="queryForm" method="post">
    <input type="text" name="question" placeholder="Ask a business question...">
    <button type="submit">Ask</button>
  </form>
  <div id="spinner" style="display:none">Analyzing... (this may take 3–7 minutes on GPU)</div>

  {% if error %}
    <div class="error">{{ error }}</div>
  {% endif %}

  {% if result %}
    {% if result.narrative %}
      <div class="narrative"><strong>{{ result.narrative }}</strong></div>
    {% endif %}

    {% if result.interpretations %}
      <div class="interpretations">
        <strong>Interpretations applied:</strong>
        <ul>{% for i in result.interpretations %}<li>{{ i }}</li>{% endfor %}</ul>
      </div>
    {% endif %}

    <details>
      <summary>SQL ({{ result.query_class }}, {{ result.execution.steps_taken }} step(s))</summary>
      <pre><code>{{ result.sql }}</code></pre>
    </details>

    {% if result.execution.data %}
      <table>
        <thead><tr>{% for col in result.execution.columns %}<th>{{ col }}</th>{% endfor %}</tr></thead>
        <tbody>
          {% for row in result.execution.data %}
          <tr>{% for col in result.execution.columns %}<td>{{ row[col] }}</td>{% endfor %}</tr>
          {% endfor %}
        </tbody>
      </table>
    {% elif not result.execution.success %}
      <p>Query could not be executed. {{ result.execution.failure_reason }}</p>
    {% endif %}
  {% endif %}

  <script>
    document.getElementById('queryForm').addEventListener('submit', function() {
      document.getElementById('spinner').style.display = 'block';
    });
  </script>
</body>
</html>
```

**Note:** `result` in the Jinja2 template is always a plain Python dict (from `response.json()`). Jinja2 resolves `result.narrative` as `result["narrative"]` via its attribute/key fallback — both work on dicts. No `dataclasses.asdict()` is needed or expected in T5.
