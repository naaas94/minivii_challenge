## §1. Task Statement

Build Mini Nivii — a domain-scoped NL-to-SQL BI agent. This subtask implements the `db` FastAPI service: CSV ingestion with ISO date normalization, SQLite persistence, and three endpoints (`POST /execute`, `GET /schema`, `GET /health`). The `db` service is the only service that touches the raw `data.csv` file.

**Non-goals:**
- Python business logic in `nlp` or `ui` services
- Multi-table schema; the `sales` table is the only table
- Any LLM calls; this service is pure data
- Continuous test regression; eval harness is the gate (built in T6)

## §2. Shared Contracts

### Error Envelope (binding for this subtask)

| Endpoint | Success shape | Error shape |
|---|---|---|
| `POST /execute` | `{"columns": [...], "rows": [[...], ...], "row_count": N}` | `{"error": "message", "sql": "..."}` |
| `GET /schema` | `{"ddl": "CREATE TABLE sales (...)"}` | HTTP 500 with `{"error": "..."}` |
| `GET /health` | `{"status": "ok", "row_count": N}` | HTTP 500 |

**Critical:** T4's `SQLExecutor._try_execute` parses these exact field names (`columns`, `rows`, `row_count`, `error`). Any deviation here is a contract violation.

### Naming
- Port: **8001** (frozen)
- Docker service name: **`db`** — used as hostname `http://db:8001` by nlp
- Volume mount: `./data.csv:/app/data.csv:ro` (set in T1's docker-compose)
- CSV path inside container: `/app/data.csv`
- SQLite path inside container: `/app/sales.db` (ephemeral; recreated on each startup)

### Types
- `quantity` column: **REAL** (not INTEGER). One row in the dataset has `quantity = 0.5`.
- `date` column: **TEXT** in ISO format `YYYY-MM-DD` after normalization (source is `M/D/YYYY`)
- `ticket_prefix` column: **TEXT** — extracted from `ticket_number`, values: `FCA | FCB | NCA | NCB`

### Tests
No unit tests required for T2. Smoke test: `GET /health` returns `{"status": "ok", "row_count": 24212}` when the container starts with the actual `data.csv`.

## §4. Subtask Spec

**Scope:** Implement the `db` FastAPI service with CSV ingestion (ISO date normalization) and three endpoints. This is the only service that reads `data.csv`.

**Files to touch:**
- `db/main.py`
- `db/ingest.py` (or inline in main.py — executor's choice)

**Files provided by T1 (do not recreate):**
- `db/Dockerfile`
- `db/requirements.txt` (fastapi, uvicorn[standard], pydantic)

**Contract bindings:** §2 Error Envelope (exact JSON shapes), §2 Naming (port 8001, service name `db`), §2 Types (quantity REAL, ticket_prefix column).

**Inputs:** T1 — directory scaffold, Dockerfile, requirements.txt.

**Outputs:**
1. `db/ingest.py` — `load_csv_to_db(csv_path, db_path)` function (verbatim from spec §5.1)
2. `db/main.py` — FastAPI app:
   - Calls `load_csv_to_db('/app/data.csv', '/app/sales.db')` at startup (via lifespan event or `@app.on_event("startup")`)
   - `POST /execute` — executes arbitrary SQL against the SQLite db, returns envelope
   - `GET /schema` — returns the DDL as rendered by `SemanticLayer.render_ddl()` or as a hardcoded string matching spec §5.2
   - `GET /health` — returns `{"status": "ok", "row_count": N}`

**Kill criteria:**
- HALT if date normalization uses `substr()` instead of `datetime.strptime('%m/%d/%Y').strftime('%Y-%m-%d')`
- HALT if `quantity` DDL type is `INTEGER` instead of `REAL`
- HALT if `POST /execute` success response does not include all three keys: `columns`, `rows`, `row_count`
- HALT if `POST /execute` error response omits the `"sql"` key
- HALT if `GET /health` response does not include `row_count`
- HALT if `ticket_prefix` column is missing from the DDL and not extracted during ingestion
- HALT if `load_csv_to_db` is not called at container startup before any endpoint serves requests
- HALT if `load_csv_to_db` is invoked via a background task that could race with the first request — use FastAPI's `@app.on_event("startup")` lifespan handler (synchronous blocking call), or the `lifespan` context manager (`asyncio.to_thread` is acceptable but the load must complete before the server begins accepting connections)
- HALT if the service does not fail loudly when `/app/data.csv` does not exist

**Risks & mitigations:**
- `data.csv` is volume-mounted read-only. Add an explicit `os.path.exists('/app/data.csv')` check before calling `load_csv_to_db`; raise a clear error if absent.
- SQLite `INSERT executemany` with 24,212 rows is fast (~0.5s). No async complications — call `load_csv_to_db` synchronously inside `@app.on_event("startup")`. Do not use `BackgroundTask` or `asyncio.create_task` for ingestion; it must complete before the server begins serving requests.
- `POST /execute` should use a try/except around `conn.execute(sql)` to catch SQLite errors and return the error envelope rather than raising HTTP 500.

## Key Implementation Reference

### `ingest.py` — verbatim from spec §5.1

```python
import csv
import sqlite3
from datetime import datetime

def load_csv_to_db(csv_path: str, db_path: str) -> None:
    conn = sqlite3.connect(db_path)
    conn.execute("""
        CREATE TABLE IF NOT EXISTS sales (
            date          TEXT,
            week_day      TEXT,
            hour          TEXT,
            ticket_number TEXT,
            ticket_prefix TEXT,
            waiter        TEXT,
            product_name  TEXT,
            quantity      REAL,
            unitary_price INTEGER,
            total         INTEGER
        )
    """)

    with open(csv_path) as f:
        reader = csv.DictReader(f)
        rows = []
        for r in reader:
            iso_date = datetime.strptime(r['date'], '%m/%d/%Y').strftime('%Y-%m-%d')
            ticket_prefix = r['ticket_number'].split()[0]
            rows.append((
                iso_date,
                r['week_day'],
                r['hour'],
                r['ticket_number'],
                ticket_prefix,
                r['waiter'],
                r['product_name'],
                float(r['quantity']),
                int(r['unitary_price']),
                int(r['total']),
            ))

    conn.executemany(
        "INSERT INTO sales VALUES (?,?,?,?,?,?,?,?,?,?)",
        rows
    )
    conn.commit()
    conn.close()
```

  → Verify the mount path. If the file is absent, raise at startup: `raise RuntimeError(f"data.csv not found at {csv_path}")`.
