# Changelog

## eval-enhancement — 2026-05-27

- Host Ollama routing: `LLMClient.resolve_ollama_url()` probes host Ollama (`host.docker.internal:11434`) on first inference call and falls back to the Compose `ollama` service when unreachable; removed hardcoded `OLLAMA_URL` from `docker-compose.yml`; `/health` reports the resolved URL. Rationale: Docker Ollama on Windows/Mac runs CPU-only by default, producing multi-hour eval wall clock; host Ollama uses GPU/Metal without a setup script. Documented measured runs and platform notes in `runtime_performance.md`. + updated `nlp/tests/test_llm_client.py`. Deferred: no integration test that probes host then container inside a running Compose stack.

- T5 (P5 narrative hardening): Hardened `_build_synthesis_prompt` with a comparative/derived/temporal constraint block (`Do not compare`, `Only report arithmetic`) and enriched `judge_synthesis` via `_judge_business_rules_block` using `TEST_CASES.known_answer` lookup plus returns/week-over-week question heuristics. Rationale: judge failures clustered on unsupported comparatives and invented temporal labels, not scalar reporting. Case 12 has `known_answer=None` so judge enrichment does not fire there until `result_assertions` lands (Flag 7). Deferred: no test that judge prompt includes returns rules when `known_answer` is None but question mentions returns (heuristic path untested in isolation).

- T4 (P3 classifier override): Added `AGGREGATION_OVERRIDES` and post-scan heuristic in `classify` so ranking terms (e.g. `most bought`, `top`) beat TIME_FILTER when both co-occur; new `nlp/tests/test_query_classifier.py` covers case 1, case 2 regression, and bare-`most` guard. Rationale: case 1 matched `on friday` before `most` due to KEYWORD_CLASS_MAP iteration order. Deferred: no test for override when TIME_FILTER keyword appears only in an ISO date suffix on `resolved` (T2 anchor uses digit-only dates).

- T3 (P2 returns constraint): Added `RETURNS_TRIGGERS`, inject `-- REQUIRED: filter return rows with WHERE total < 0` into `build_sql_prompt` when trigger terms appear in the question, and extended AGGREGATION few-shot with a returns example using `total < 0`. Rationale: case 12 executed but omitted the returns filter because the SQL model ignored domain semantics. Deferred: no test for false-positive trigger on phrases like "return customers" (accepted residual).

- T2 (P1 temporal anchor): Added `SemanticLayer.get_date_anchor()`, anchored `recent` disambiguation to `date_range.end` minus 30 days (replacing wall-clock-relative apply text when `semantic_layer` is passed), wired `semantic_layer` through `pipeline.py`, and enriched 0-row SQL observer messages with dataset `date_range` bounds. Rationale: case 11 returned 0 rows because “recent” used calendar-relative dates against a static 2024 dataset. Deferred: no test that `get_date_anchor()` rejects malformed ISO in `date_range.start` after YAML load.

- T1 (P4 eval phase 1 — execution gate): Added `execution_pass` to harness case rows and JSONL output; redefined `case_pass` as structural gates plus execution success; added `EvalReport.tier_summary` (`structural`, `execution`, `composite`). README eval table now documents exec and tier pass rates. Rationale: the prior 83% structural headline ignored failed executions (case 11). Deferred: no test that written `eval_*.json` rows contain every legacy key plus `execution_pass` (covered indirectly by `run_eval` mocks).
